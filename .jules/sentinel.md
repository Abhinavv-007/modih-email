## 2024-05-06 - Add Security Headers
**Vulnerability:** Missing basic security headers like HSTS, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, and Content-Security-Policy.
**Learning:** For Cloudflare Pages projects, standard security headers can be enforced by adding a `_headers` file in the static build output directory (`public/_headers` in this case).
**Prevention:** Include a standard `_headers` file when setting up new Cloudflare Pages projects to enforce baseline defense-in-depth protections.

## 2024-05-24 - Replace Math.random() with Crypto API
**Vulnerability:** Weak random number generation using `Math.random()` for critical or pseudo-random unique elements like UUIDs and boundary strings. This is predictable and insecure.
**Learning:** `Math.random()` should never be used where unpredictability is required, even for "fallback" UUIDs or multipart boundaries in email formats. An attacker could potentially predict values generated by `Math.random()`. The codebase already has precedent for avoiding it (e.g. `_api-helpers.js`, `api/inbox.js`), but some client-side instances remained.
**Prevention:** Always use `crypto.getRandomValues()` or `crypto.randomUUID()` when generating random identifiers, UUIDs, or strings to ensure cryptographically secure generation.
